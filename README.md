# Homework

Трекер домашних заданий поверх расписания группы. Расписание тянется напрямую
с публичного API ЛКС МГТУ им. Баумана (`lks.bmstu.ru`) и обновляется раз в
сутки автоматически; дз-комментарий общий для группы, отметка «выполнено» —
персональная для каждого. Вход по имени и паролю, у каждого предмета свой
цвет, можно сразу занести дз на следующее занятие по этому же предмету.
React + Express/TypeScript + PostgreSQL, всё в Docker.

## Быстрый старт (локально)

Нужен установленный Docker (с Docker Compose v2).

```bash
cp .env.example .env        # при желании поменяй пароль постгреса
./scripts/setup.sh          # поднимает контейнеры, накатывает миграции и сидирует расписание
```

По умолчанию `scripts/setup.sh` использует дату начала семестра `2026-08-31`
(понедельник той недели, на которую приходится 1 сентября 2026) —
**поправь `--start` под свой реальный первый день семестра** (обязательно
понедельник — `seed.ts` проверяет это и откажется запускаться на другой день
недели), иначе числитель/знаменатель будут определяться неверно. Смотри флаги
внутри самого скрипта.

После этого:

- Фронтенд (dev, hot-reload): http://localhost:5173
- Бэкенд API напрямую: http://localhost:4000/api/health

Миграции создают дефолтный админский аккаунт — **`admin` / `admin123`**
(пароль короче 6 символов система не пропускает, поэтому не буквально
`admin`). **Смени пароль сразу после первого входа** (раздел «Админ» →
«Пользователи» → «Сменить пароль») — это широко известный дефолт. Дальше
зарегистрируй (или создай через «Админ» → «Пользователи») аккаунт для
каждого одногруппника отдельно — все видят общее расписание и общие
дз-комментарии, но отметка «выполнено» у каждого своя. Не забудь зайти в
раздел «Админ» и через поиск найти свою группу в ЛКС (например «ИУ8-13»),
чтобы прописать `bmstu_group_uuid` — тогда ежедневная синхронизация будет
брать расписание именно с сервера, а не только из изначально засеянного
JSON.

### Без setup.sh, вручную

```bash
cp .env.example .env
docker compose up -d --build
docker compose run --rm backend npm run migrate
docker compose run --rm backend npm run seed -- --semester="Осень 2026" --start=2026-08-31
```

## Синхронизация расписания

`backend` раз в сутки (03:00 по Москве) сам обращается к
`https://lks.bmstu.ru/lks-back/api/v1` и сверяет расписание группы,
указанной в активном семестре (`bmstu_group_uuid`), с тем, что лежит в базе:

- новые пары — добавляются;
- у существующих пар при смене преподавателя/аудитории/типа — обновляются
  поля на месте (id пары не меняется, привязанное дз не теряется);
- пары, пропавшие из расписания — помечаются неактивными (**не удаляются**),
  дз на их датах просто перестаёт отображаться со ссылкой на пару, но не
  теряется.

Каждый прогон пишется в журнал — раздел «Админ» → «Синхронизация с ЛКС»
показывает, что и когда изменилось. Там же есть кнопка «Синхронизировать
сейчас» для ручного запуска, не дожидаясь ночи.

`bmstu_schedule.py` в корне репозитория — независимый ручной скрипт-экспортёр
(делает то же самое, но выгружает в автономный HTML-файл); он не используется
рантаймом, оставлен как справочный инструмент/фолбэк для сверки вручную.

## Вход, цвета предметов, дз на следующее занятие

- **Вход по имени и паролю.** Регистрация создаёт отдельный аккаунт (пароль
  хранится как bcrypt-хеш); при входе выдаётся JWT-токен на 30 дней, который
  фронтенд хранит в `localStorage` и шлёт заголовком `Authorization: Bearer
  …`. `JWT_SECRET` в `.env` подписывает эти токены — `scripts/setup.sh`
  генерирует его случайным при первом запуске (нужен `openssl`), иначе
  сгенерируй сам: `openssl rand -hex 32`. Расписание и дз-комментарии общие
  для всех аккаунтов группы, отметка «выполнено» — только своя.
- **Цвет предмета.** Каждому предмету гарантированно присваивается свой цвет
  из палитры (`GET /api/subjects` отдаёт список предметов активного семестра
  по алфавиту, фронтенд раскрашивает по порядку) — это надёжнее случайного
  хеша, который на 12+ предметах почти наверняка даёт совпадения.
- **«Дз на след. занятие».** На карточке любого занятия есть кнопка
  «дз на след. занятие →» — жмёшь её прямо во время пары и вносишь
  комментарий сразу в *следующее* занятие по этому предмету (тот же
  `lesson_template`, ближайшая дата с подходящим днём недели и чётностью),
  не листая календарь вперёд вручную.

## Продакшен на своём VPS

```bash
# на сервере, после установки Docker:
git clone <this-repo> homework && cd homework
cp .env.example .env        # обязательно смени POSTGRES_PASSWORD
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
docker compose run --rm backend npm run migrate
docker compose run --rm backend npm run seed -- --semester="Осень 2026" --start=2026-08-31
```

Фронтенд (nginx) слушает порт 80. Если нужен HTTPS на своём домене — проще
всего поставить перед стеком Caddy или Traefik отдельным контейнером/сервисом
(не входит в этот compose по умолчанию, чтобы не навязывать конкретный
domain/DNS-сетап).

### Бэкапы

```bash
docker compose exec postgres pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" > backup-$(date +%F).sql
```

Стоит повесить это в cron на самом VPS (не внутри контейнера).

### Обновление после `git pull`

```bash
git pull
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
docker compose run --rm backend npm run migrate
```

Новые SQL-миграции (файлы в `backend/src/db/migrations/`) накатываются сами
по возрастанию имени файла — уже применённые пропускаются.

## Структура проекта

```
backend/   Express + TypeScript API, миграции, сидер, синхронизация с ЛКС
frontend/  React + Vite, недельный/месячный календарь, админка
docker-compose.yml            postgres + backend + frontend
docker-compose.override.yml   dev-оверрайды (hot-reload), грузится по умолчанию
docker-compose.prod.yml       прод-оверрайды для VPS
```

Известные ограничения и осознанные компромиссы: общий комментарий к дз
сохраняется по принципу «кто последний сохранил» без блокировок при
одновременном редактировании; смена пароля/восстановление через email не
реализованы (только регистрация нового аккаунта) — приемлемо для небольшой
доверенной группы.
